# Releasing kirke

kirke is released with [Hephaestus](https://github.com/magicdrive/hephaestus)
(`hephaestus.yaml`). Pushing a `v*` tag runs `.github/workflows/release.yml`,
which publishes the GitHub Release and opens a pull request on
[magicdrive/homebrew-tap](https://github.com/magicdrive/homebrew-tap). Nothing
is published from a pull request or from a workstation.

## Prerequisites (repository settings)

`make publish-check vX.Y.Z` verifies every row it can read (secret names
only, never values). These are the
[Hephaestus publish conventions](https://github.com/magicdrive/hephaestus/blob/main/docs/publish.md#conventions):

| Item | Value |
| --- | --- |
| Ruleset on `main` | Active branch ruleset covering `main` with the required status check `ci-gate` |
| Ruleset on tags `refs/tags/v*` | Active; forbids **deletion** and **update** (not creation) |
| Environment `release` | Deployment restricted to **tags** `v*` only (no branch policy); required reviewers are optional |
| Secret in `release` | `HOMEBREW_TAP_GITHUB_TOKEN`: a fine-grained token (or GitHub App token) with `contents: write` and `pull-requests: write` on `magicdrive/homebrew-tap` only. Stable releases only; prereleases never receive it |
| Release token | The workflow's `GITHUB_TOKEN` (`contents: write` in the `release` job only). `PERSONAL_GITHUB_TOKEN` is no longer used |
| Locally | `git`, an authenticated `gh` (`gh auth status`), Go, GNU Make 3.81 or later, a clone whose `origin` is `magicdrive/kirke` |

## Steps

1. Merge everything for the release into `main` and wait for the CI run of
   the push to `main` to pass (`ci-gate`).
2. Optionally run the preflight alone (read-only: git state, CI on the
   commit, the release workflow, rulesets, environment, tap token name, and
   `hephaestus preflight --strict`):

   ```sh
   make publish-check vX.Y.Z
   ```

3. Release:

   ```sh
   make publish vX.Y.Z            # or VERSION=vX.Y.Z, or tag=vX.Y.Z as before
   ```

   It runs the same preflight, asks for confirmation (default No; `YES=1`
   skips the prompt), creates and pushes one annotated tag, then follows
   the `Release` workflow — `ci` (the full CI at the tag), `build` (build,
   archive, checksum; read-only) and `release` (plan, tap rehearsal,
   provenance attestation, GitHub Release, tap pull request) — and verifies
   the published release: assets and checksums, attestations, release notes,
   and the tap pull request (or that the tap was left alone for a
   prerelease).
4. Review and merge the pull request "Brew formula update for kirke version
   vX.Y.Z" on magicdrive/homebrew-tap. `make publish` never merges it.

Release notes are generated by GitHub from the merged pull requests.
Prerelease tags (`vX.Y.Z-rc.1`) are published as prereleases and do not
update the tap: the release job's plan step reports `tap=skip`, so the two
tap steps are skipped and never receive the tap token.

`make publish-status vX.Y.Z` shows what exists for a version (read-only);
`make publish-help` explains the safety rules.

### Changes from the former `make publish tag=vX.Y.Z`

The former target ran `make release-build` and then `git tag` and
`git push origin <tag>`; GoReleaser then built and published the release
with `PERSONAL_GITHUB_TOKEN` and committed the formula to the tap directly.
`make publish` now runs `hephaestus publish`:

- the version may be given as `make publish vX.Y.Z`, `VERSION=vX.Y.Z` or
  `tag=vX.Y.Z` (exactly one), and must be `vMAJOR.MINOR.PATCH[-PRERELEASE]`;
- it first runs a preflight (git state, CI on the commit, rulesets,
  environment, the release workflow conventions and
  `hephaestus preflight --strict`);
- it asks before tagging, creates an **annotated** tag (formerly
  lightweight), and re-checks `origin/main` and the remote tag right before
  the push;
- after the push it follows the release run and verifies the release
  instead of returning immediately. Ctrl-C stops only the monitoring:
  continue with `make publish-watch vX.Y.Z`.

`make preflight tag=vX.Y.Z` runs `hephaestus preflight --strict` alone. The
tap now receives a pull request instead of a direct commit.

## What a release contains

Unchanged from the GoReleaser releases up to v1.2.8, and checked by
`scripts/verify-dist.sh` in CI and before publishing:

- `kirke_<version>_<os>_<arch>.tar.gz` for darwin/amd64, darwin/arm64,
  linux/386, linux/amd64, linux/arm64, windows/386, windows/amd64 and
  windows/arm64 (tar.gz on Windows too), each with `kirke` (`kirke.exe`) at
  the root and `completions/` (`kirke-completion.sh`,
  `bash/kirke-completion.bash`, `zsh/_kirke`);
- `kirke_checksums.txt` (`sha256sum -c` format);
- `kirke --version` prints `kirke version vX.Y.Z`.

The binaries are built with the Go toolchain pinned in `hephaestus.yaml`
(`builds[].env.GOTOOLCHAIN`), whatever Go is installed; v1.2.8 was built with
go1.24.2. `verify-dist.sh` checks the toolchain recorded in every binary.

`make snapshot` builds the same files locally (version `0.0.0-SNAPSHOT`).

## Homebrew formula

Hephaestus generates `kirke.rb` from `brews` in `hephaestus.yaml`. Compared
with the GoReleaser formula of v1.2.8, it passes `brew audit --strict`:

- no `version` line: Homebrew infers it from the release URLs;
- `desc` comes from `project.description`: at most 80 characters, without
  a trailing period (`TestFormulaDescription` checks it);
- one `def install` at the class level instead of one per `on_macos` /
  `on_linux` block;
- the test runs `kirke --version` and one conversion through
  `shell_output("#{bin}/kirke ...")` / `pipe_output` instead of
  `system "#{bin}/kirke"`.

The binary and the bash (`kirke`) and zsh (`_kirke`) completions are
installed to the same places as before. `make e2e-homebrew` (CI job
`homebrew-e2e`) installs the tap's v1.2.8 formula, then upgrades to the
generated one and runs `brew style`, `brew audit --strict`, `brew test` and
`brew uninstall`.

## Recovery

A lost connection, Ctrl-C or a timeout stops the monitoring, not the
release (exit code 3, "outcome unknown"):

```sh
make publish-status vX.Y.Z   # tag, run, release, assets, attestations, tap
make publish-watch vX.Y.Z    # find and follow the run again, then verify
```

- **Stopped before the push:** at most a local tag exists
  (`git tag -d vX.Y.Z`, then start again).
- **The workflow failed before `Publish the GitHub Release`:** nothing is
  public. A transient failure: re-run the failed jobs. A code fix: merge it
  and release a new version (for example the next `-rc.N`); tags are never
  moved or deleted.
- **It failed during or after the release step:** re-run the failed jobs.
  Hephaestus continues idempotently: identical assets are left alone, and the
  tap pull request is reused. A published release's assets are never
  replaced; release a new patch version instead.
- **The tap pull request was not opened:** re-run the `release` job.

See the Hephaestus [publish guide](https://github.com/magicdrive/hephaestus/blob/v1.3.0/docs/publish.md#recovery)
and [recovery guide](https://github.com/magicdrive/hephaestus/blob/v1.3.0/docs/recovery.md).
